# Vitest 기반 기본 테스트 추가 계획

## Summary

- `vitest`만 개발 의존성으로 설치하고, 현재 라이브러리 소스인 `src/tarot.js`를 직접 테스트한다.
- 테스트 범위는 핵심 로직만 포함한다: deck 초기화, spread 관리, reading 생성, 주요 error case.
- coverage, deck JSON 스키마 검증, 브라우저/UMD bundle 테스트는 이번 작업에서 제외한다.

## Key Changes

- `package.json`
  - `devDependencies`에 `vitest` 추가.
  - `scripts`에 아래 명령 추가:
    - `"test": "vitest run"`
    - `"test:watch": "vitest"`
  - 기존 `"build"` 스크립트는 유지.
- `package-lock.json`
  - `npm install -D vitest` 실행 결과로 갱신.
- 신규 테스트 파일
  - `test/tarot.test.js` 생성.
  - `src/tarot.js`를 직접 import한다: `import Tarot from "../src/tarot.js";`

## Test Cases

- Deck initialization
  - 유효한 카드 배열로 `initializeDeck()` 호출 시 deck count와 cards가 반환되는지 확인.
  - 반환된 deck 배열과 내부 카드 객체가 freeze되는지 확인.
  - 빈 배열, 배열이 아닌 값, 배열 내부의 invalid card가 error를 던지는지 확인.
- Spread management
  - `addSpread()`가 positions, description, cardCount를 저장하는지 확인.
  - `listSpreads()`가 추가된 spread 이름을 반환하는지 확인.
  - `getSpreadInfo()`가 spread 정보를 반환하는지 확인.
  - `removeSpread()` 후 해당 spread 조회 시 error가 나는지 확인.
- Reading flow
  - deck과 spread가 준비된 상태에서 `doReading()`이 `{ position, card }` 배열을 반환하는지 확인.
  - `getCurrentSpread()`가 최근 reading을 반환하는지 확인.
  - deck 초기화 전 `drawCards()` 또는 `doReading()` 호출 시 error가 나는지 확인.
  - 존재하지 않는 spread로 `doReading()` 호출 시 error가 나는지 확인.
- Draw behavior
  - `drawCards(count)`가 요청한 개수만큼 카드를 반환하는지 확인.
  - deck 크기보다 많이 뽑으려 하면 error가 나는지 확인.
  - 랜덤 순서 자체는 검증하지 않고, shape과 count 중심으로 검증한다.

## Verification

- 구현 후 실행할 명령:
  - `npm install -D vitest`
  - `npm test`
  - `npm run build`
- 성공 기준:
  - `npm test`가 통과한다.
  - 기존 `npm run build`가 계속 통과한다.
  - 테스트 추가로 public API나 `dist/` import 경로를 변경하지 않는다.

## Assumptions

- 이번 작업은 "핵심 로직만" 테스트하는 최소 도입으로 진행한다.
- coverage 도구와 coverage threshold는 추가하지 않는다.
- deck JSON 데이터 검증 테스트는 후속 작업으로 남긴다.
- 테스트는 빌드된 `dist/`가 아니라 원본 `src/tarot.js`를 대상으로 한다.

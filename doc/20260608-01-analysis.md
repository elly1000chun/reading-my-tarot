# Repository Structure Analysis

## 1. 프로젝트 한 줄 요약

`Tarot.js`는 Tarot deck JSON 데이터를 받아 카드 덱, 커스텀 spread, 랜덤 reading을 제공하는 순수 JavaScript 라이브러리입니다.

## 2. 기술 스택

- Package manager: `npm` (`package-lock.json` 존재)
- Runtime/module: Node.js, ESM 기반 (`"type": "module"`)
- Library entry:
  - 소스 엔트리: `src/tarot.js`
  - 배포 엔트리: `dist/tarot.min.js`, `dist/tarot.min.cjs`, `dist/tarot.umd.min.js`
- Build tool: Webpack 5
- Transpile/minify: Babel, Terser
- Framework: 없음. React/Vue/Next 같은 앱 프레임워크가 아니라 라이브러리 패키지입니다.
- Test framework: 현재 없음

## 3. 디렉터리별 역할

- `src`: 라이브러리 원본 코드와 빌드 설정
  - `tarot.js`: `Tarot` 클래스 구현
  - `webpack.config.babel.js`: UMD/ESM/CJS 번들 생성 설정
  - `license.config.js`: 빌드 산출물에 삽입할 라이선스 배너 및 출력 포맷 설정
- `dist`: 빌드된 배포 파일
  - npm `main`, `browser`, `exports`가 이 파일들을 가리킵니다.
- `decks`: Tarot deck 데이터
  - `decks/en/default.json`, `decks/en/waites.json`
- `.github`: GitHub Actions와 issue template
  - `.github/workflows/build.yaml`: 수동 실행 빌드 및 결과 커밋 워크플로
- 루트:
  - `package.json`: 패키지 메타데이터와 빌드 스크립트
  - `README.md`: 사용 예시와 프로젝트 설명

## 4. 주요 실행 흐름

사용자는 `Tarot` 클래스를 import한 뒤 인스턴스를 만들고, JSON deck 배열을 `initializeDeck(cards)`로 등록합니다. 이후 `addSpread(name, { positions, description })`로 spread를 추가하고, `doReading(spreadName)`을 호출하면 deck에서 spread의 카드 수만큼 랜덤 draw 후 position과 card를 매핑해 반환합니다.

핵심 상태는 `deck`, `currentSpread`, `customSpreads`, `isInitialized`입니다. deck은 초기화 시 각 카드 객체와 배열을 freeze해서 외부 변형을 줄이려는 구조입니다.

## 5. 테스트/빌드/실행 명령

- 의존성 설치: `npm install` 또는 CI 기준 `npm i`
- 빌드: `npm run build`
- 테스트: 정의된 테스트 스크립트가 없습니다.
- 라이브러리 사용: README 예시처럼 ESM import 또는 패키지 export를 통해 사용합니다.

## 6. 신규 개발자가 먼저 읽어야 할 파일

1. `README.md`
2. `package.json`
3. `src/tarot.js`
4. `src/webpack.config.babel.js`
5. `src/license.config.js`
6. `decks/README.md`
7. `decks/en/default.json`

## 7. 구조상 리스크 또는 개선점

- 테스트가 없습니다. `initializeDeck`, `addSpread`, `drawCards`, `doReading`, error handling에 대한 최소 단위 테스트가 필요합니다.
- `shuffleDeck()`은 초기 `Object.freeze`된 deck을 이후 일반 배열로 바꿉니다. 불변성 정책이 일관되지 않습니다.
- `default.json`과 `decks/README.md` 출력에서 문자 깨짐이 보입니다. 파일 인코딩 또는 표시 환경 문제를 확인해야 합니다.
- `webpack.config.babel.js`는 ESM import를 쓰면서 마지막에 `module.exports`를 사용합니다. 현재 빌드가 동작할 수는 있어도 모듈 시스템 혼용은 유지보수 리스크입니다.
- GitHub Actions는 `workflow_dispatch` 수동 실행만 있고, 테스트 없이 빌드 결과를 커밋/푸시합니다. PR 검증용 CI로는 부족합니다.
- deck JSON 스키마가 코드로 검증되지 않습니다. 일부 카드에는 `type`, `value`, `suit`가 빠진 항목이 보여 데이터 일관성 검증이 필요합니다.
